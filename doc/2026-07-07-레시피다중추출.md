# 2026-07-07 작업 기록

## 1. URL/사진에 레시피가 여러 개면 첫 번째만 등록되던 문제 해결

### 1-1. 원인 분석
- `RecipeExtractService`가 Claude에게 "반드시 단일 JSON 객체로만 응답 (배열 금지)"를 프롬프트로 강제.
- 혹시 배열로 응답이 와도 `extractJsonNode()`에서 `node.get(0)` — 첫 번째 요소만 취하고 나머지는 버림.
- URL 추출(`extract`), 이미지 Vision 추출(`extractFromImages`) 둘 다 동일 구조.

### 1-2. 구현 방식 결정
- 후보 3가지 논의:
  1. 한 번에 배열로 추출 + 프론트 카드 목록에서 선택 등록
  2. 한 번에 배열로 추출 + 확인 없이 전체 자동 등록
  3. 목록(제목)만 먼저 추출 → 사용자 선택 → 선택 항목만 2차 상세 추출
- **선택: 방식 1** — Claude API 호출 1번으로 끝나고(2, 3안과 달리 추가 호출 없음), 사용자가 각 레시피를 확인/수정 후 원하는 것만 저장 가능.

### 1-3. 백엔드 변경 (`RecipeExtractService`, `RecipeExtractController`)
- URL/Vision 프롬프트를 "단일 객체 금지" → "반드시 JSON 배열로 응답, 레시피가 여러 개면 배열 요소로 분리, 하나면 요소 1개 배열" 로 변경.
- `extractJsonNode()` → `extractJsonNodes()`로 교체: 배열의 첫 요소만 취하던 로직 제거, 전체 배열을 `List<JsonNode>`로 반환.
- `parseResult`, `parseVisionResult`가 각각 `List<RecipeExtractResponse>`를 반환하도록 변경. Vision 쪽은 레시피가 여러 개여도 이미지 번호(`finishedImageIndex`, `stepImageIndex`)를 전체 사진 기준 번호로 공유해서 매핑.
- `extract()` / `extractFromImages()` 반환 타입 `RecipeExtractResponse` → `List<RecipeExtractResponse>`, 각 레시피마다 이미지 다운로드/단계 이미지 매핑을 개별 적용.
- 컨트롤러 응답 타입도 `ApiResponse<List<RecipeExtractResponse>>`로 변경.

### 1-4. 프론트엔드 변경 (`RecipeForm.jsx`, `RecipeForm.module.css`)
- `ExtractedRecipeList` 컴포넌트 신규 추가: 추출된 레시피들을 카드(썸네일·제목·설명)로 보여주고, 미저장 항목엔 "확인하기" 버튼, 저장된 항목엔 "✅ 등록 완료" 배지 표시.
- `extractedList` / `activeIndex` state 추가:
  - 추출 결과가 2개 이상 → 목록 화면 표시 (`activeIndex === null`)
  - 1개면 기존처럼 폼에 바로 채움 (변경 없음)
- 카드 "확인하기" 클릭 → `openForEdit(i)`: 기존 상세 폼(재료/단계/이미지 등)에 해당 레시피 데이터를 채워서 보여줌. "← 목록으로" 버튼으로 저장 없이 목록 복귀 가능.
- 저장 성공 시 해당 카드만 `_saved: true` 처리 + 폼 초기화 후 자동으로 목록 화면 복귀 — 나머지 레시피는 그대로 남아서 원하는 것만 반복 등록 가능.
- "완료하고 나가기" 버튼으로 언제든 종료(홈으로 이동).

### 1-5. 검증
- `frontend`: `npm install` 후 `npm run build` 성공 (JSX 문법 이상 없음 확인).
- `backend`: `./gradlew compileJava` 성공.
