# 2026-07-30 작업 기록 (웹소켓 라우팅 수정 + 유저 검색 기능)

## 1. 채팅 WebSocket 핸드셰이크가 SpaController에 가로채이는 문제 수정 (이슈 #7)

### 1-1. 원인
- `SpaController`의 SPA fallback 정규식(`/{path:^(?!uploads$|assets$)[^\\.]*$}`)이 `/ws`에도 매칭됨
- 이 컨트롤러가 매핑된 `RequestMappingHandlerMapping`(order 0)이 STOMP의 `WebSocketHandlerMapping`(order 1)보다 먼저 조회되어, 핸드셰이크 요청이 실제 WebSocket 업그레이드(101) 대신 `index.html` forward(200)로 가로채여졌음
- `2026-07-23-채팅기능구현.md`에서 구현한 채팅 기능이 실 브라우저 E2E 미실시 상태로 남아있었는데, 실제로 붙여보니 핸드셰이크 자체가 안 되는 문제가 있었던 것

### 1-2. 해결
- 정규식 네거티브 룩어헤드 제외 목록에 `ws` 추가: `^(?!uploads$|assets$|ws$)[^\\.]*$`
- `doc/2026-06-10.md`에서 `uploads` 경로를 같은 방식으로 제외했던 전례와 동일한 패턴

## 2. SonarCloud가 지적한 SpaController 기존 코드 스멜 정리

### 2-1. 배경
- `SpaController`는 처음 만들어질 때부터 두 가지 문제가 있었음: path 템플릿 변수를 파라미터에 바인딩하지 않음(S6856), HTTP 메서드 미명시(S3752)
- 이번 PR에서 같은 줄의 정규식을 수정하면서 SonarCloud의 "new code" 판정에 걸려 Quality Gate가 막힘 → 겸사겸사 정리

### 2-2. 변경
- `@RequestMapping`에 `method = RequestMethod.GET` 명시
- `forwardToIndex()`에 `@PathVariable String path` 파라미터 추가

## 3. 닉네임 기반 유저 검색 기능 추가 (이슈 #8)

### 3-1. 배경
- 레시피를 작성한 적 없는 유저는 프로필로 갈 링크가 없어 팔로우도 채팅도 시작할 수 없었음

### 3-2. 백엔드
| 파일 | 변경 내용 |
|------|-----------|
| `UserRepository.java` | `searchByNickname()` — LIKE 검색 + 본인 결과 제외(`excludeId`), 페이징 |
| `UserService.java` | `searchUsers()` — 검색 결과마다 팔로워/팔로잉 수, 현재 유저 기준 팔로우 여부 포함 |
| `UserController.java` | `GET /api/users/search?keyword=` 추가. 기존 `GET /api/users/**`가 `permitAll`이라 `SecurityConfig` 변경 불필요 |

### 3-3. 프론트엔드
| 파일 | 변경 내용 |
|------|-----------|
| `pages/UserSearch.jsx` | `/users/search` 페이지 신규. 검색 → 결과 목록에서 팔로우 토글/채팅하기 바로 가능 |
| `pages/UserSearch.module.css` | 스타일 (신규) |
| `App.jsx` | `/users/search` 라우트 추가 |
| `components/Navbar.jsx` | 유저 검색 링크 추가 |
