# 2026-07-27 작업 기록

## 1. 로그인 세션이 유지되지 않던 문제

"로그인했다가 재접속하면 로그인된 것처럼 보이는데 실제로는 다시 로그인해야 한다"는 증상에서 출발.
원인이 프론트엔드 1개 + 백엔드 2개로 총 3개였다.

### 1-1. 회전된 refreshToken을 저장하지 않음 (프론트, 근본 원인)

- **What**: `axios.js`의 401 인터셉터가 `/auth/refresh` 응답에서 `accessToken`만 저장하고 새 `refreshToken`을 버리고 있었다.
- **Why 문제인가**: `AuthService.refresh()`는 호출마다 refreshToken을 회전(rotation)시켜 새로 발급하고 **기존 토큰을 DB에서 삭제**한다. 프론트가 새 토큰을 저장하지 않으니, 최초 1회 갱신 이후에는 이미 삭제된 옛 토큰으로 요청하게 되어 갱신이 **반드시** 실패했다. refreshToken 만료가 7일이어도 실제로는 그 전에 세션이 끊겼다.
- 갱신 실패 시 catch 블록이 `localStorage.clear()` + `/login` 이동을 하므로 강제 로그아웃으로 이어졌다.

### 1-2. 동시 요청 시 race condition (프론트)

- **What**: 갱신 요청을 `refreshPromise` 하나로 묶어 중복 호출을 제거.
- **Why**: 페이지 진입 시 여러 API가 동시에 401을 받으면 각자 독립적으로 `/auth/refresh`를 호출한다. 첫 요청이 성공하며 토큰을 회전시키면 나머지는 무효해진 토큰으로 실패 → 정상 세션이 통째로 날아갔다.

```js
let refreshPromise = null
function refreshAccessToken() {
  if (!refreshPromise) {
    refreshPromise = axios.post(...).then(...).finally(() => { refreshPromise = null })
  }
  return refreshPromise
}
```

### 1-3. 같은 초에 발급된 JWT가 완전히 동일 (백엔드)

- **What**: `JwtProvider.buildToken()`에 `jti`(UUID) 클레임 추가.
- **Why**: `iat`/`exp`가 **초 단위**라, 같은 사용자가 1초 이내에 토큰을 두 번 발급받으면 payload가 같아져 **JWT 문자열이 바이트 단위로 동일**해진다. `refresh_tokens.token`의 UNIQUE 제약에 걸려 500이 나고, 프론트는 이를 갱신 실패로 보고 저장소를 비웠다.
- **재현**: 동시 로그인 2건 → 한쪽이 `{"success":false,"message":"이미 존재하는 데이터입니다."}`. 백엔드 로그에 `Duplicate entry 'eyJhbGciOiJIUzM4NCJ9...' for key 'UK_ghpmfn23...'`.
- **탭을 여러 개 열어두면 실사용에서도 재현된다.** `refreshPromise`는 한 페이지 안의 동시 호출만 막아준다.
- Hibernate는 트랜잭션 내에서 INSERT를 DELETE보다 먼저 flush하므로, `refresh()`의 `delete(stored)` + `save(new)`에서 새 토큰이 옛 토큰과 같으면 **반드시** 충돌했다. jti 한 줄로 login/refresh 양쪽이 함께 해소됐다.

### 1-4. 사용자당 세션이 1개뿐 (백엔드)

- **What**: `login()`의 `refreshTokenRepository.deleteByUserId()` 제거 → 기기별 동시 로그인 허용.
- **Why**: 로그인할 때마다 기존 세션의 refreshToken을 전부 지워서, 다른 기기에서 로그인하면 기존 기기가 조용히 로그아웃됐다. (조사 중 내가 `test@test.com`으로 API 로그인을 호출한 것 때문에 사용자 세션이 끊긴 일도 있었다.)
- 만료 토큰이 쌓이지 않도록 로그인 시 `deleteByExpiresAtBefore()`로 정리.
- `logout(userId, refreshToken)`으로 해당 세션만 종료하도록 변경. **토큰 소유자를 확인**해 남의 refreshToken으로 세션을 끊을 수 없게 막았다.
- 트레이드오프: 1세션 정책을 "새 기기 로그인 시 기존 기기 로그아웃"이라는 보안 장치로 볼 수도 있으나, 일반 서비스 관행에 맞춰 멀티 세션을 택했다.

## 2. 자동 로그인 ("로그인 상태 유지")

- **What**: 로그인 화면에 체크박스 추가. 저장 위치 결정을 `tokenStorage.js` 모듈로 분리.

| 체크 | 저장소 | 동작 |
|------|--------|------|
| O | `localStorage` | 7일 sliding — 갱신할 때마다 만료가 7일 뒤로 재설정 |
| X | `sessionStorage` | 브라우저 종료 시 로그아웃 |

- **Why 이 설계**: 서버의 `refresh-token-expiry`(7일)는 그대로 두고 **저장 위치만** 체크박스로 제어. 백엔드 변경이 0이면서 의미 있는 차이가 난다. 네이버 등이 쓰는 옵트인 방식과 같다.
- `authPersist` 플래그를 `localStorage`에 두고 `tokenStorage`가 이를 보고 두 저장소 중 하나를 고른다. 나머지 코드는 어디에 저장되는지 몰라도 된다.
- `stomp.js`의 WebSocket 인증도 같은 경로를 쓰도록 통일.
- 로그아웃이 `localStorage.clear()`로 앱의 다른 저장값까지 지우던 것을 인증 키 3개만 제거하도록 축소.

## 3. CI 수정

- `sonarcloud-analyze.yml`의 `java-version: '17'` → `'21'`
- **Why**: SonarQube Cloud가 Java 17 지원을 중단해 분석이 **항상** 실패하고 있었다 (`The version of Java (17) ... no longer supports it`). 어떤 PR을 올려도 빨간불이었다.
- 분석 전용 JDK만 상향. `cd.yml`(배포 빌드)과 `sourceCompatibility`는 17 유지 → 산출물 영향 없음.

## 6. 로컬 실행 환경 정리 (재발 방지)

- `application.yml`의 local 프로파일에 **datasource 설정이 없다.** `application-prod.yml`에만 있어서 그냥 `bootRun`하면 기동 실패.

```bash
./gradlew bootRun --args='--spring.datasource.url=jdbc:mysql://localhost:3306/baby_recipe?useSSL=false&serverTimezone=Asia/Seoul&characterEncoding=UTF-8 --spring.datasource.username=root --spring.datasource.password=root --spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver'
```

- 로컬 MySQL은 **5.7.13**, 접속 `root`/`root`. `GETTING_STARTED.md`의 `password`는 틀렸고 문서가 요구하는 8.0도 아니다. Hibernate가 "5.7 no longer supported" 경고를 내지만 정상 동작한다.
- DB `baby_recipe`를 이 날 새로 생성. 테스트 계정 `test@test.com` / `test1234`.
- 셸에서 `curl -d`로 한글 JSON을 보내면 인코딩이 깨져 500이 난다 — 앱 버그 아님. ASCII로 테스트할 것.

### 인코딩 설정 추가 (`build.gradle`)

```groovy
tasks.withType(JavaCompile).configureEach { options.encoding = 'UTF-8' }
tasks.named('bootRun') {
    jvmArgs '-Dstdout.encoding=UTF-8', '-Dstderr.encoding=UTF-8', '-Dfile.encoding=UTF-8'
}
```

- **Why**: JVM 기본이 `stdout.encoding = MS949`라 `System.out.println("한글")`이 `?????`로 깨졌다. `build.gradle`에 컴파일 인코딩 설정도 없었다.
- ⚠️ 이 설정은 **아직 실제 한글 출력으로 검증하지 못했다** (테스트용 println이 중간에 원복됨). 미커밋 상태.
