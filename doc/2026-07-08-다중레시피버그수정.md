# 2026-07-08 작업 기록

## 1. URL 다중 레시피 추출 시 응답 잘림으로 실패하던 문제 수정

### 1-1. 증상 및 원인 분석
- 사용자 제보: `https://m.blog.naver.com/hw_loves_hssh/224255756864` (볶음밥 레시피 4종 모음 블로그)처럼 레시피가 여러 개인 URL을 추출하면 실패함.
- `RecipeExtractService.callClaude()`에서 Claude API 호출 시 `max_tokens`가 2048로 고정되어 있었음.
- 레시피 1개는 문제없지만, 레시피가 여러 개면 응답 JSON에 대표 이미지 URL + 단계별 이미지 URL(각 150~200자 pstatic.net URL)이 레시피 수만큼 반복되며 2048 토큰을 초과 → 응답이 잘려 JSON 파싱 실패(`레시피 정보를 추출할 수 없습니다`).
- 실제 해당 URL을 직접 받아 구조 분석(Jsoup 모듈 파싱 재현) 결과 파인애플볶음밥/밥새우볶음밥/대파달걀볶음밥/달걀찜밥 4개 레시피 확인, 분량상 2048 토큰 초과가 유력한 원인으로 판단.

### 1-2. 수정
- `max_tokens` 2048 → 8192로 상향 (`RecipeExtractService.java`). URL/Vision 추출 모두 공유하는 값이라 함께 적용.

### 1-3. 검증
- 라이브 서버(EC2)에 임시 테스트 계정으로 로그인 후 `POST /api/recipes/extract`를 실제 URL로 호출 → 레시피 4개 모두 정상 추출 확인 (응답 시간 약 23초).

## 2. 다중 레시피 대표 이미지가 엉뚱한 레시피 사진으로 매칭되는 문제 수정 (2차례)

### 2-1. 1차 수정: 레시피별 대표 이미지 매칭 규칙 부재
- 네이버 블로그용 프롬프트(`buildNaverStructuredContent` + `callClaudeText`의 이미지 매칭 지시문)는 조리 단계(step) 이미지 매칭 규칙("바로 앞이나 뒤")만 있었고, 레시피 전체 대표 이미지(`imageUrl`)는 페이지 전체에 하나뿐인 og:image만 알려줄 뿐, 레시피가 여러 개일 때 각각 어떻게 골라야 하는지 규칙이 없었음.
- 실제 테스트 결과 마지막 레시피("달걀찜밥")의 `imageUrl`이 `null`로 나옴 — Claude가 임의로 뒤쪽 이미지를 대표 이미지로 쓰다가 마지막 레시피는 뒤에 이미지가 없어 실패.
- 1차 수정: "레시피가 여러 개면 각 레시피의 섹션(자기 제목~다음 레시피 제목 직전) 안의 이미지를 대표 이미지로 사용" 규칙 추가.
- 재배포 후 테스트: 4개 레시피 모두 `imageUrl`이 채워짐 (달걀찜밥도 포함) → 1차적으로는 성공한 것처럼 보였음.

### 2-2. 실제로는 여전히 오배치 — 이미지 직접 다운로드로 확인
- 사용자 재확인 요청: "각 레시피 대표 이미지가 안 맞아".
- 원본 이미지 4장(IMG_1954, IMG_2882, IMG_3902, IMG_3895)을 직접 다운로드해 눈으로 대조한 결과, 이 블로그는 **하나의 "식판샷" 사진에 그날의 반찬 6~7가지가 전부 라벨로 표시된 구조**였음. 블로그 본문 순서는 `[식판 이미지] → [레시피 제목/캡션] → [레시피 본문]`이 4번 반복되며, 사진은 항상 **자기 레시피 제목보다 앞(위)**에 위치.
- 1차 수정의 "자기 제목~다음 제목 직전" 섹션 정의가 실제로는 **본문 뒤·다음 레시피 제목 바로 앞의 이미지(=다음 레시피 것)**까지 포함해버려서, 결과적으로 모든 레시피가 한 칸씩 밀려 **다음 레시피의 식판사진**을 대표 이미지로 가져가고 있었음. (예: "파인애플볶음밥"이 실제로는 "밥새우볶음밥" 식판사진을 사용)
- 2차 수정: 규칙을 "자신의 제목 T: 줄보다 **앞에** 있는 가장 가까운 I[N] 이미지를 사용하고, 본문 뒤에 나오는 이미지는 이미 다음 레시피 것이므로 사용 금지"로 방향을 명확히 고정.

### 2-3. 최종 검증
- 재배포 후 각 레시피의 `imageUrl`을 실제로 다운로드하여 Read 도구로 이미지를 직접 열어보고, 이미지 안의 음식 라벨과 레시피명이 일치하는지 육안 대조.
- 파인애플볶음밥/밥새우볶음밥/대파달걀볶음밥/달걀찜밥 4개 모두 정확히 매칭 확인.

## 3. 다중 레시피 목록에서 "전체 등록" 버튼 추가

### 3-1. 배경
- 기존에는 다중 레시피 추출 시 카드 목록에서 "확인하기" → 상세 폼 열람 → 저장을 레시피마다 반복해야 했음.
- 여러 개를 한 번에 등록하고 싶은 니즈가 있어 일괄 등록 버튼 요청받음.

### 3-2. 구현 (`RecipeForm.jsx`, `RecipeForm.module.css`)
- `ExtractedRecipeList`에 "전체 등록 (N개 남음)" 버튼 추가.
- `saveAllExtracted()`: 아직 저장 안 된 레시피를 순서대로 `POST /recipes`로 저장, 성공 시마다 해당 카드에 "✅ 등록 완료" 배지 실시간 반영.
- 일부 레시피 저장이 실패해도 나머지는 계속 진행하고, 종료 후 실패한 레시피 제목을 에러 메시지로 안내.
- 등록 진행 중에는 "확인하기"/"전체 등록"/"완료하고 나가기" 버튼 모두 비활성화해 중복 클릭 방지.
- `buildCreateBody()`: 추출 결과(`RecipeExtractResponse` shape)를 `POST /recipes` 요청 바디로 변환하는 헬퍼 (재료/단계 필터링, order 재부여).

### 3-3. 검증
- `npm run build` 통과 확인.
- 브라우저 자동화 도구가 없어, 버튼이 호출하는 것과 동일한 저장 로직(레시피별 `POST /api/recipes`)을 라이브 서버에 대해 재현 — 4개 레시피 모두 201 Created로 정상 등록되는 것을 확인 후, 테스트로 만든 레시피는 삭제하여 정리.
